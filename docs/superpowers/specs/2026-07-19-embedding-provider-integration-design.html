Embedding Provider Integration — Detailed Design

Date: 2026-07-19 · Revision 3 Scope: Embed stage only (Phase 1) Depends on: PR #375 (RustDbWriter) Rust + PyO3

Architecture Overview

The embed stage is a single std::thread between Parser and DB Writer. It holds no DB connection and no Python references. It owns a Box<dyn EmbeddingProvider> wrapping a reqwest::blocking::Client. The GIL is released during the entire pipeline — never re-acquired by the embed stage.

Dimension truncation is provider-internal. The embed stage never sees native dimensions — it only calls provider.embed_batch() and receives vectors at provider.dimensions(). The bloom filter key includes the output dimension to correctly distinguish same-model-different-dims embeddings.

Config fields: output_dims (target dimension) and client_side_truncation (where truncation happens).

// Example: "a1b2c3:openai:text-embedding-3-small:1536"

False positive rate: 1%. False negatives: never.

Error Propagation & Pipeline Shutdown

stateDiagram-v2 [*] --> Running: start state Running { Receiving --> Accumulating: chunk passes bloom Accumulating --> Flushing: batch full / drain Flushing --> Receiving: success Flushing --> ErrorState: retries exhausted Receiving --> Draining: Parser done / cancelled Draining --> [*]: all files emitted } state ErrorState { MarkCancelled: set cancelled=true MarkVectorsNone: un-flushed batch → None EmitPendingFiles: partial results out DropSender: signal DB Writer PropagateError: return Err [*] --> MarkCancelled MarkCancelled --> MarkVectorsNone MarkVectorsNone --> EmitPendingFiles EmitPendingFiles --> DropSender DropSender --> PropagateError PropagateError --> [*] } Running --> ErrorState: unrecoverable error
Key invariant: The safety-net drain ALWAYS runs before error propagation. This ensures the DB Writer receives the drop signal and doesn't hang, even when the embed stage fails catastrophically.

HTTP Status → Error Classification

fn classify_response(response: Response) -> Result<Response, EmbedError> {
    match response.status().as_u16() {
        200..=299 => Ok(response),                                    // success
        401 | 403 => Err(EmbedError::Auth(body)),                     // auth failure
        429 => {
            let retry_after = parse_header(&response, "retry-after");
            Err(EmbedError::RateLimited { retry_after })               // rate limit
        }
        400..=499 => {
            if body.contains("context length") {
                Err(EmbedError::ContextLengthExceeded(body))           // splittable
            } else {
                Err(EmbedError::BadRequest(body))                      // fatal
            }
        }
        500..=599 => Err(EmbedError::Provider(body)),                 // server error
        _ => Err(EmbedError::Http(format!("HTTP {}", status))),       // unknown
    }
}

Retry & Error Handling Implementation

struct RetryPolicy {
    max_attempts: u32,       // default: 3
    base_delay:   Duration,  // 1 second
    max_delay:    Duration,  // 60 seconds
    jitter:       bool,      // true
}
fn embed_with_retry(
    provider: &dyn EmbeddingProvider,
    texts: &[String],
    policy: &RetryPolicy,
    cancelled: &AtomicBool,
    stats: &mut EmbedStats,
) -> Result<Vec<Vec<f32>>, EmbedError> {
    let mut attempt = 0;
    let mut delay = policy.base_delay;
    loop {
        if cancelled.load(Relaxed) { return Err(EmbedError::Cancelled); }
        attempt += 1;
        match provider.embed_batch(texts) {
            Ok(v) => { /* validate len, return */ }
            Err(e) => {
                stats.retries += 1;
                if matches!(e, ContextLengthExceeded(_)) { return Err(e); }
                if !is_retryable(&e) || attempt >= policy.max_attempts {
                    stats.chunks_failed += texts.len() as u64;
                    return Err(e);
                }
                let wait = parse_retry_after_or_backoff(&e, delay);
                sleep_with_jitter(wait, policy.jitter);
                if !matches!(e, RateLimited { .. }) {
                    delay = (delay * 2).min(policy.max_delay);
                }
            }
        }
    }
}

Token Estimation

const EMBEDDING_CHARS_PER_TOKEN: usize = 3;  // matches Python

fn estimate_tokens(text: &str) -> usize {
    text.len() / EMBEDDING_CHARS_PER_TOKEN
}

Logging — pyo3-log Bridge

The embed stage (and all Rust pipeline stages) use the log crate macros. The pyo3-log crate routes every Rust log::*!() call to Python's logging module — a single bridge, no separate Rust log file, no format syncing.

# Cargo.toml
[dependencies]
pyo3-log = "0.10"
log      = "0.4"

// src/lib.rs
#[pymodule_init]
fn init_module(_py: Python, m: &Bound<'_, PyModule>) -> PyResult<()> {
    pyo3_log::init();                     // routes all log::*! → Python logging
    pyo3::prepare_freethreaded_python();  // required for embed thread callbacks
    Ok(())
}

What NOT to Do

  • Don't use env_logger: writes to stderr independently, bypassing Python's log routing and CHUNKHOUND_DEBUG_FILE.
  • Don't use print!() / eprintln!(): no log level control, no file routing, no MCP protocol support.
  • Don't route debug messages through progress callback: too chatty — use log::debug!() instead.
  • Don't use log::error!() for parse failures: errors go in PipelineReport.errors; log::warn!() is for operational warnings.
